# 接口、Mock 与持久化

## 请求组织

- 沿用项目已有请求入口。首次接入时按需组织 `src/api/`。`config.ts` 管理 API 前缀，`request.ts` 处理请求、响应和通用错误，`modules/` 和 `types/` 按业务域存放接口方法与契约类型。
- 页面或负责业务流程的 Hook 调用业务方法，展示组件通过 Props 和回调交互。接口响应在数据边界从 `unknown` 开始校验。
- 前端使用同源 `/api` 路径。代理和部署配置见[验证与部署](verification-and-deployment.md#环境与部署)。
- 独立请求并发发起，多个区块共用同一次查询时，由共同父层或已有缓存复用结果。条件快速变化时，防止过期响应覆盖当前结果。

## Mock 与页面状态

- Mock 用明确的开发开关启用，与真实接口共用契约和错误语义，覆盖正常、空值、失败和边界数据。
- 生产默认关闭 Mock。真实请求失败时展示约定的错误或空态。
- 按需处理首屏加载、局部刷新、无数据、失败及只读状态。区分数值 `0` 与缺失值。数据写入成功后再显示成功结果。

## 前端持久化

- 需要刷新后恢复时才持久化非敏感数据。存储键包含项目和业务域，结构带版本号，集中处理校验、迁移和重置。
- 临时筛选、悬停和弹窗状态保存在内存。损坏或无法读取的数据回退到默认值。访问授权由服务端校验。

# 页面与组件开发

## 有原型时

1. 保留原始 HTML 和相对路径资源。使用设计稿时，记录可见区块、已有状态和待确认的交互。
2. 梳理区块、数据来源、布局、滚动边界和关键操作。按区块迁移为 React 组件，将 DOM 拼接和事件代理改为声明式渲染。
3. 用相同的数据和视口对照原型，核对默认值、筛选、确认、取消、重置和空态，记录差异及待确认事项。

## 无原型时

1. 明确页面用途、用户角色、首版主流程、字段口径、目标浏览器和部署路径。
2. 梳理页面区块、数据流、操作结果和异常状态。先实现可独立运行的核心流程，再补齐边界。
3. 记录待确认事项，按首版流程验证页面状态和操作结果。

## 目录、路由与样式

- `index.html` 和 `src/main.tsx` 是唯一的 HTML 与 React 挂载入口。`src/App.tsx` 装配路由。独立 URL 页面在 `src/routes.tsx` 中登记并按需加载，页内视角用 React 状态切换。
- 页面入口为 `src/pages/<PageName>/index.tsx`。页面专用组件、布局和数据转换随页面组织。跨页复用组件放入 `src/components/`，组件目录以 `index.tsx` 为入口，按实际需要建目录。
- 全局基础样式放在 `src/styles/base.less`，专用 Less 样式随组件维护。父层负责区块排列、间距和滚动边界，宽表在自身容器内横向滚动。

## 组件、状态与编码

- 按可独立维护的业务区块拆分组件。使用函数组件和声明式渲染，用户操作放在事件回调中。Effect 用于外部同步、DOM 测量或焦点管理，监听、订阅和定时器随组件清理。列表使用稳定 ID。
- 局部状态留在使用它的组件，共享状态放到最近的共同父层。子树内深层共享时按需使用 Context，跨页共享优先复用项目现有方案。
- 派生值从现有数据计算，草稿与已应用值分别管理。明确应用、取消和重置时机。级联筛选中，父级改变时一次更新需要重置的子级与页码。
- 显式定义组件 Props 和业务模型。外部数据在边界校验，结构未知时用 `unknown` 接收，避免用 `any` 或未经校验的类型断言绕过检查。
- 组件和组件目录使用 PascalCase，函数和变量使用 camelCase，事件 Props 以 `on` 开头。代码遵循 Prettier 配置，控制语句使用大括号，由 ESLint 的 `curly` 规则校验。
- 图表等重型模块按页面或首次使用动态加载。昂贵派生计算按需缓存。

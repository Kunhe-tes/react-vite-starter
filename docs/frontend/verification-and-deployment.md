# 验证与部署

## 环境与部署

- 提交 `.env.example` 记录配置字段，本机配置放在被忽略的 `.env.local`。带 `VITE_` 前缀的变量只放公开值。
- 开发代理由 `VITE_API_PROXY_TARGET` 启用，转发时保留 `/api` 前缀。生产环境的 API 转发由部署侧配置。
- `VITE_BASE_PATH` 默认是 `/`，子路径部署时设为实际路径。为页面路由配置 SPA 回退，验证直接访问、刷新、静态资源、动态分包和 API 请求。缺失的资源和 API 错误保留各自的响应。
- JavaScript 和 CSS 的 Vite 构建目标为 `chrome108`。新增浏览器 API 或 CSS 特性时核对目标内核兼容性。

## 验证与提交

提交前执行仓库现有检查。

```sh
npm run format:check
npm run typecheck
npm run lint
npm run build
```

- 功能改动在浏览器实测核心流程、布局、焦点，检查控制台与网络请求。常规视觉检查使用 1920×1080 和 1440×960，有指定视口时按需求验证。
- 涉及持久化时检查保存、刷新恢复和无效数据回退。记录实际验证的浏览器与结果，Chromium 108 的验收在目标内核完成。
- 验证后停止专为验证启动的服务，构建产物、截图和临时文件留在提交范围之外。
- 使用 Conventional Commits，按变更目的拆分提交。交接时记录验证结果和待确认事项。
